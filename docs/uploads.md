# File uploads

`POST /api/v1/uploads` accepts authenticated `multipart/form-data` requests. Add each file using the `files` field. A request can contain up to 10 files by default, with a 15 MB limit per file.

```bash
curl --request POST http://localhost:5000/api/v1/uploads \
  --header "Authorization: Bearer <access-token>" \
  --form "files=@vehicle-front.heic" \
  --form "files=@insurance-policy.pdf"
```

Images are detected from their content, resized to a maximum width of 1920 pixels without enlargement, converted to WebP at quality 80, and uploaded to an immutable object key. Supported inputs are JPEG, PNG, WebP, AVIF, GIF, TIFF, SVG, HEIC, and HEIF. PDFs are validated and uploaded without image conversion.

```json
{
  "success": true,
  "message": "Files uploaded successfully",
  "data": {
    "files": [
      {
        "key": "uploads/images/2026/08/785a4187-3f45-43e1-8dca-56194809aa72.webp",
        "url": "https://cdn.kokki.in/uploads/images/2026/08/785a4187-3f45-43e1-8dca-56194809aa72.webp",
        "type": "image",
        "contentType": "image/webp",
        "originalContentType": "image/heic",
        "originalName": "vehicle-front.heic",
        "originalSize": 2849132,
        "size": 312845,
        "width": 1920,
        "height": 1440
      }
    ]
  }
}
```

Configuration is controlled by `AWS_*`, `CDN_BASE_URL`, `UPLOAD_*`, and `IMAGE_*` variables documented in `.env.example`. Static credentials are supported for local development; when they are omitted, the AWS SDK uses its default credential chain, so an ECS task role, EC2 role, or other workload identity can be used in production. The S3 identity only needs `s3:PutObject` and `s3:DeleteObject` for the configured bucket prefix.

## Delete an asset

`DELETE /api/v1/uploads` deletes one upload using either its returned object key or its full Kokki CDN URL. This endpoint requires an access token and only accepts the UUID-based `uploads/images/...` and `uploads/documents/...` keys generated by the upload API.

Delete by key:

```bash
curl --request DELETE http://localhost:5000/api/v1/uploads \
  --header "Authorization: Bearer <access-token>" \
  --header "Content-Type: application/json" \
  --data '{"key":"uploads/images/2026/08/785a4187-3f45-43e1-8dca-56194809aa72.webp"}'
```

Delete by CDN URL:

```json
{
  "url": "https://cdn.kokki.in/uploads/images/2026/08/785a4187-3f45-43e1-8dca-56194809aa72.webp"
}
```

Successful response:

```json
{
  "success": true,
  "message": "Asset deleted successfully",
  "data": {
    "asset": {
      "key": "uploads/images/2026/08/785a4187-3f45-43e1-8dca-56194809aa72.webp",
      "url": "https://cdn.kokki.in/uploads/images/2026/08/785a4187-3f45-43e1-8dca-56194809aa72.webp",
      "cdnInvalidation": {
        "id": "I2ABCDEFG12345",
        "status": "InProgress"
      }
    }
  }
}
```

S3 deletion is idempotent, so deleting a missing key also succeeds. When `AWS_CLOUDFRONT_DISTRIBUTION_ID` is configured, the API submits an invalidation for the deleted path; the AWS identity then also needs `cloudfront:CreateInvalidation`. Without that configuration, `cdnInvalidation` is `null`, and an already cached CDN response can remain available until its cache entry expires.
